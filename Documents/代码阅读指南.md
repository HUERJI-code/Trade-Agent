## 第一次读 Python 时常见的语法

| 写法 | 本项目中的含义 |
|---|---|
| `import` / `from ... import ...` | 取得别的文件或库提供的功能，不等于调用所有函数。 |
| `def name(...):` | 定义函数，调用时才执行缩进内的代码。 |
| `class` / `self` | 把相关数据和行为组织成对象；self 表示当前对象。 |
| `if` / `elif` / `else` | 根据条件选择一个分支。 |
| `for ... in ...` | 对集合中的元素逐一处理。 |
| `with` | 使用具有上下文协议的对象；文件和这里的数据库连接会按各自协议清理资源。SQLite 连接上下文主要管理事务。 |
| `try` / `except` / `finally` | 尝试执行、处理错误，以及无论成功失败都做的清理。 |
| `raise` / `return` | raise 报错并中断当前正常流程；return 把结果交还给调用方。 |
| `None` / `NULL` / `null` | 分别是 Python、SQL、JSON/YAML 中的空值表示，不等于数字 0。 |
| `f'...{value}...'` | 把变量放进文本；SQL 中的外部值仍需要参数化或可靠的字面量编码。 |
| `[... for ... in ...]` | 列表推导式，一行表达“逐项处理并收集结果”。花括号可用于字典或集合推导式。 |
| `@pytest.fixture` | 给测试提供可复用的数据准备函数。 |
| `assert` / `pytest.raises` | 检查结果是否符合预期；后者验证某个操作应该报错。 |

## 用一个问题串起来

在项目终端运行下面的只读查询：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m tools.business_tool --metric revenue --start 2019-01-01 --end 2020-01-01 --country Germany
```

1. `main()` 取得指标 ID `revenue`、日期和国家参数。
2. `run_metric()` 创建只读引擎，读取真实结构，加载正式字典。
3. YAML 给出 `SUM(s.quantity * p.unit_price_usd)` 公式。
4. `query()` 加上 `s.order_date >= '2019-01-01'`、`s.order_date < '2020-01-01'` 和 `c.country = 'Germany'`。
5. 校验器确认 SQL 符合允许规则，重新生成查询。
6. 执行器通过只读连接执行覆盖检查及指标查询，转换结果并写脱敏日志。
7. 返回的 `columns` 与每一行 `rows` 按位置对应。`metric_value` 的结果为 `1874921.45` 美元，`matching_sales_lines` 为 `2208` 条明细。

这是 2019 年德国客户的**估算销售额**。匹配明细数不等于订单数，金额来自数量乘产品标价。

Phase 3 现在已经可以用中文提问，并自动完成参数提取：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m agent.cli --question "2019年德国销售额是多少？"
```

命令需要项目 Ollama 服务处于运行状态。当前已启动；电脑重启后，在 PowerShell 7 中运行 `./scripts/local_model.ps1 start`。模型已经下载好，不要重复执行 download。

返回中的 `plan` 是模型理解后的筛选条件，`result` 是真实数据库结果，`usage` 是模型运行统计。遇到 `clarify` 时，请重新输入包含完整条件的问题；当前命令之间还不保留历史上下文。
