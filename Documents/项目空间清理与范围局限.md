## 当前项目能做什么

项目定位是基于公开零售数据的本地业务问数与 Agent 工程实践。技术链路是：

**React 页面 → FastAPI → LangGraph 会话与流程 → LangChain 工具调用 → 受控查询计划 → Python 生成 SQL → 只读 MySQL → LoRA 组织回答 → 事实检查与模板回退。**

- 六个指标：估算销售额、估算毛利、估算毛利率、订单数、活跃客户数、销量。
- 单次指定一个指标、一个明确日期区间、一个国家或全部国家；可按月份、客户国家、产品类别中的一种维度分组。
- 明确年/月的国家最高、最低问题有专门支持，并保留并列结果；不等于实现任意 Top N 排名。
- 支持新建、切换及保存会话，连续追问可继承部分已确认条件，缺条件时可以补充；分组结果可展示表格和 Plotly 图表。
- Qwen3-8B 在本地 Ollama 部署，LoRA 训练用于回答格式、措辞和口径表达；实际数字来自数据库计算。
- 数据库只读、字段白名单、敏感信息限制、SQL 校验及异常回答回退继续生效。

## 当前局限与原因

| 边界 | 实际含义 |
|---|---|
| 数据范围 | Kaggle Global Electronics Retailers 教学数据，交易覆盖 2016-01-01 至 2021-02-20、8 个客户国家；没有实时同步企业业务数据 |
| 金额真实性 | 缺少实际成交价、折扣、税运费、退货和历史成本，只能按产品美元标价和成本估算；无法据此报告真实收入或净利润 |
| 查询表达能力 | 当前计划只表达一个指标、一个日期区间、一个或全部国家及一种分组；多国筛选、多期间同比环比、任意维度、复杂 Top N、预测尚未实现 |
| 自然语言转 SQL | 模型输出受约束的工具参数，Python 按业务字典生成 SQL；没有开放模型任意编写和执行 SQL |
| LoRA 能力 | 主要学习回答风格，不会新增数据库字段、查询维度或工具能力，也不是专门训练 Text-to-SQL |
| 对话理解 | 依赖有限条件继承规则与模型解析，复杂指代、歧义、长程上下文仍可能失败；校验不能证明所有语义理解正确 |
| 并发与权限 | 本机单用户运行，会话 ID 用来区分聊天；没有企业账号、角色权限或多租户隔离，一次只执行一个分析请求，忙时返回 429 |
| 生产能力 | 未实现生产级数据同步、任务队列、分布式服务、完整运维监控，也没有接入文档 RAG 或通用报表系统 |

例如“2019年德国销售额比2018年增加多少”目前可能被拦截，是因为查询计划与执行工具尚不能在一个请求中表达、执行两个期间并计算差值。解除字符串拦截本身不足以让这个问题正确执行，需要扩展计划结构、查询工具、比较计算和对应验证。数据库只读和敏感字段保护应独立保留。

## 如何理解已有评估结果

此前 234 项离线测试、16 个现场查询/会话场景通过，说明这些已测试流程可用，不代表任意业务问题都正确。

两组 206 条原始回答评估中，微调后风格更符合要求，但全部样本自动检查通过率从 98.06% 变为 94.66%；其中正常结果子集从 98.65% 变为 99.32%。不能据此声称模型全面提升或业务准确率达到某个生产指标。数据包含同一事实的不同问法和模拟边界，评估也不是全面语义证明。

因此当前仍保留可信事实校验与模板回退。完整指标及失败案例见 [训练评估与部署结果](LoRA训练评估与部署结果.md) 和 [失败样例复核](LoRA失败样例复核.md)。
