# Qwen3-8B 本地部署：所有模型文件保存在 D 盘项目内

项目目录：`D:\Codex\Trade Agent`。下面记录已经执行的部署步骤，方便理解和复现。现有机器已经下载好模型，不需要重复下载。

## 1. 模型与运行器各是什么

- **Qwen3-8B** 是开源语言模型，权重决定它如何理解文本。本项目下载的是 Ollama 提供的 **Q4_K_M 量化版本**，文件约 5.2 GB。8B 指约八十亿参数，不表示模型文件恰好 8 GB。
- **Ollama** 是负责加载权重、使用 CPU/GPU 进行推理并提供本机 HTTP 接口的运行器。
- **Python Agent** 向本机 Ollama 发送问题与业务规则，拿到指标参数，再调用 MySQL 工具。模型不会直接登录数据库。

Ollama 的 Windows 独立 CLI 可以从官方发布的 ZIP 部署，无需运行默认安装到用户目录的向导。[官方 Windows 文档](https://docs.ollama.com/windows)

## 2. 已确认的本机配置

- 系统内存约 32 GB。
- NVIDIA GeForce RTX 4060 Laptop GPU；Ollama 实际识别为 8 GiB 显存，启动时约 6.9 GiB 可用。
- 内置 Intel Arc 核显没有被本次推理选用。
- Windows 的 `Win32_VideoController.AdapterRAM` 在大显存设备上可能不能正确表示容量，本次以运行器识别结果为准。

先采用 4096 token 上下文、单并行请求和一个驻留模型。扩大上下文会增加缓存占用，不能把 5.2 GB 模型文件大小当作推理时的全部内存/显存需求。

## 4. 部署脚本的四个动作

脚本：`D:\Codex\Trade Agent\scripts\local_model.ps1`，需要 PowerShell 7。可直接阅读其中中文注释。

| 命令 | 做什么 | 是否需要联网 |
|---|---|---|
| `./scripts/local_model.ps1 download` | 下载固定版本独立运行包，校验后解压 | 首次需要 |
| `./scripts/local_model.ps1 start` | 启动项目内运行器，仅监听本机 | 启动本身不下载模型 |
| `./scripts/local_model.ps1 pull` | 从 Ollama 模型仓库下载 qwen3:8b，由运行器校验权重 | 首次或补齐下载需要 |
| `./scripts/local_model.ps1 status` | 检查程序位置、本机服务与模型目录配置 | 不需要外网 |

运行包固定为 **Ollama 0.33.3**，ZIP 约 1.47 GB。下载来源是 `ollama/ollama` 官方 GitHub 发布资产，SHA-256：

```text
52cb36a62e7e501f61514f60212dec7117b6c098811357585e02fffe32d2fcd7
```

脚本先写 `.part` 文件；支持断点续传，校验一致后才标记完整并解压。已有运行目录不会被自动覆盖，ZIP 条目在解压前会检查是否超出目标路径。[官方发布](https://github.com/ollama/ollama/releases/tag/v0.33.3)

实际拉取命令相当于 `ollama pull qwen3:8b`，但脚本使用 D 盘运行器的绝对路径，避免误调用其他安装。[模型标签及量化说明](https://ollama.com/library/qwen3:8b)

## 5. 为什么不会把模型放到 C 盘

启动服务前，脚本给子进程指定：

```text
OLLAMA_MODELS=D:\Codex\Trade Agent\models\ollama
OLLAMA_HOST=127.0.0.1:11434
OLLAMA_NO_CLOUD=1
```

同时将子进程的 USERPROFILE、LOCALAPPDATA、APPDATA、TEMP、TMP 指向项目 `.runtime` 下的目录。没有修改 PowerShell 的 HOME，也没有改系统或当前账号的永久配置。

服务启动日志已确认 `OLLAMA_MODELS` 指向 D 盘、`Ollama cloud disabled: true`。应用 HTTP 客户端另外拒绝外部模型 URL、系统代理和重定向。安装包与权重的首次下载需要外网；业务问题推理走本机服务。

不要另开一个使用默认环境的 Ollama 服务再拉模型，否则那个服务可能使用自己的默认保存目录。脚本遇到已有 11434 服务会拒绝重复启动；先用 status 检查当前服务。pull 会核验运行器进程来自本项目。

## 6. 模型与业务工具怎样配合

```text
中文问题
  → Python 检查明确的缺时间、越界等情况
  → 本机 Ollama：Qwen3 提取指标、日期、国家和分组
  → Python 严格检查 JSON 及条件是否与问题一致
  → 已确认的 YAML 指标公式生成 SQL
  → SQL 白名单校验与 MySQL 只读执行
  → Python 格式化数字、估算标签、数据覆盖说明
```

模型只提取受限参数，不生成可任意执行的脚本，也不计算金额。当前的答案解释由固定模板生成，暂未实现自由撰写长篇分析。

模型调用使用 Ollama `/api/chat`，关闭流式和思考输出，通过 `format` 指定 JSON schema，并在 Python 再验证一次。[结构化输出](https://docs.ollama.com/capabilities/structured-outputs)、[Chat API](https://docs.ollama.com/api/chat)

## 7. 你现在怎么用

在项目终端执行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m agent.cli --check-model
.\.venv\Scripts\python.exe -X utf8 -m agent.cli --question "2019年德国销售额是多少？"
```

第一次加载可能较慢。此次首个完整请求约 7 秒；模型驻留后的开发样例通常约 1.3–2.1 秒，实际耗时会受其他程序、缓存和硬件状态影响。

电脑重启后只需重新执行 `./scripts/local_model.ps1 start`，已有权重不需要再下载。模型空闲 5 分钟后可从内存卸载，服务进程仍然运行；下次请求会重新加载。

## 8. 现在还没有做什么

这次是**部署别人训练好的量化模型**，没有训练基础模型，没有自行制作量化权重，也没有做 LoRA 微调。配置里的 temperature=0.1 是起始配置，不是已经完成调参实验后的最佳值。

LoRA 后续需要业务指令样本、独立训练/验证/测试划分和基线比较。不能把这里 15 条用于开发的冒烟样例当成独立测试集，也不能把所有代码测试通过称为模型问答准确率 100%。
