# Phase 1 安全数据访问层验收

2026-09-09，本机 MySQL 8.0.39，数据库 trade_agent_demo。使用专用只读账号；未接入 LLM 或修改业务数据。

## 实现结果

- SQLAlchemy/PyMySQL 连接统一到 database/connection.py；每次从连接池取连接均核对身份、表级 SELECT 权限，设置只读事务与超时。
- schema_tool 从真实库读取五张表的列、主键和外键，只向查询工具提供明确允许的业务字段。
- SQLGlot 30.18.0 解析 MySQL，检查所有查询作用域中的物理表和字段；仅校验后重新生成的 SQL 可以执行。
- 支持 SELECT、非递归 CTE、UNION、聚合与有条件 JOIN。拒绝写操作、多条语句、敏感列、系统库、危险函数、变量、文件操作、锁、注释/提示和递归查询。
- 默认最多 2000 行；保留较小 LIMIT，限制 OFFSET 与 SQL 长度/复杂度。服务端默认 5 秒超时，并有客户端超时。
- 结果包含列名、数据、行数、上限说明、执行 SQL、耗时与 trace_id；Decimal 金额以字符串保留精度。
- 审计日志保存哈希和去掉字面量、自定义别名的 SQL 模板，不写查询结果或凭证。

## 当前边界

函数与 SQL 语法采用有限允许清单，未支持的合法查询会被拒绝。没有自然语言理解、业务公式字典、前端、登录鉴权或按用户限制行访问。客户敏感字段由工具限制；数据库账号仍有五张完整教学表的 SELECT 权限。当前测试针对本教学数据与锁定的依赖版本，不是对任意 SQL 方言的完整安全证明。
