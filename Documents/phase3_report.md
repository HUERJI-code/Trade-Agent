# Phase 3 本地模型问数验收

日期：2026-09-09。项目：`D:\Codex\Trade Agent`。

## 已实现

使用 Ollama 0.33.3 与 Qwen3-8B Q4_K_M，在本机完成中文问题→结构化参数→业务指标工具→MySQL→中文结果的链路。代码没有新增云端模型调用，也没有让模型直接执行 SQL。

模型权重保存在项目 `models/ollama`；运行器在 `.runtime/ollama`。服务使用本机 `127.0.0.1:11434`，运行环境、临时文件和日志都设置在 D 盘项目下。具体部署操作见《本地模型部署指南》。

## 本阶段边界

- 支持六个已确认指标，每次一个指标、一个日期范围、一个或全部客户国家、一种分组。
- 日期支持明确年份、中文年月、两个 ISO 日期。自然语言明确起止日默认包含结束日，内部统一转换成不含结束日；用户说明“不含结束日”时保持原结束日期。
- 缺时间、相对时间和歧义范围先澄清；当前单轮 CLI 不保存上一轮，用户需重新输入完整问题。
- 标准指标公式由 approved 字典决定。未知字段、额外 SQL 属性、重复 JSON 键、越界模型配置、无效日期不会透传给数据库。
- 某些问题在应用前置检查即被拒绝或澄清，不调用模型。这是业务规则，不是冒充大模型的模拟回答。
- 模型格式或交叉核对失败最多重试一次；网络故障不会循环重试，模型不可用时不回退到云端或伪造结果。
- 答案中的金额由 Decimal 格式化，保持估算标记。超出日期范围不解释成零业务。
- 问答日志仅记录问题哈希、模型/耗时/Token 统计与查询追踪号；不写原始问题或查询结果。开发样例报告例外，只包含脚本中公开的教学问题与聚合结果。

字段与日期校验不能保证所有自然语言都被正确理解。当前已知能力范围外的问题可能保守拒绝；运行时需查看 `plan` 和筛选条件，不能将开发样例成功推广为任意问题都正确。

## 验证证据

1. 本阶段完成时既有测试加模型测试：`python -m pytest -q`，**184 passed**；后续网页阶段测试总数见 phase4_report.md。
2. 独立导入检查：`python scripts/test_import_tools.py`，**4 passed**。
3. 真正使用 Qwen3-8B 与 MySQL 的开发冒烟样例：**15/15 通过**。

样例包括六项指标、按月/品类/国家分组、缺时间、相对时间、2026 年无数据覆盖、利润含义不明、净利润不支持和数据删除拒绝。六项 2019 德国指标继续匹配阶段 2 的原始 CSV 独立对账。

首次真实查询为“2019年德国销售额是多少？”，结果 **1,874,921.45 美元**，参与明细 **2208 条**，端到端约 **6.99 秒**（含首次模型加载）。随后的 15 条验证中，正常查询约 **1.3–2.1 秒**；需明确澄清/拒绝且未调用模型的样例不能计入模型推理速度均值。

开发中第一次真实样例运行出现 13/15 通过：缺时间被模型错误标记为 query，2026 年请求被错误拒绝。之后将明确指标的缺时间规则前置，并补充“年份覆盖由数据库决定”的指令及示例。修改后的同一开发样例集为 15/15，**不是独立留出集结果，也不代表 LoRA 提升**。前次结果保留于 `work/phase3_model_smoke_before_prompt_fix.json`。
