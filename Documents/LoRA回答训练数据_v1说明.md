# LoRA 回答风格训练数据 v1

后续状态：用户已要求开始训练，见 [LoRA 训练运行指南](LoRA训练运行指南.md)。本文件记录数据生成阶段；数据内容与划分保持原样。

用户已确认回答风格。本次生成用于后续监督微调的消息数据，没有下载新的模型、安装训练依赖、运行训练或更改网页回答逻辑。数据位于 `D:\Codex\Trade Agent\Data\answer_style\v1`。

本版本共 **1,110 条**：训练集 **698 条**、验证集 **206 条**、测试集 **206 条**。其中 **862 条**基于 **401 个**只读查询快照，**170 条**为模拟情境，**78 条**为手工流程情境。每个场景有两种问法，合计 555 个场景，不应将 1,110 条描述为独立的真实业务查询。

## 数据文件怎么用

| 文件 | 用途 |
|---|---|
| `train.json` | 正式训练输入，最外层是 JSON 数组 |
| `validation.json` | 训练期间检查损失及回答质量，不能用于梯度更新 |
| `test.json` | 训练方案确定后做最终评测，不能反复据此改训练方案 |
| 同名 `.jsonl` | 对应 JSON 数组的逐行版本，每行一个样例；二选一使用，不能重复合并 |
| `provenance.json` | 每条记录的来源、事实组、数据划分、查询快照引用；不作为训练输入 |
| `manifest.json` | 总量、来源分布、生成方法、数据集来源、版本和文件摘要 |
| `validation_report.json` | 格式、重复输入、分组隔离、原句保留及文件摘要检查 |
| `audit_report.json` | 独立脚本对全部导出记录的核验结果，包含真实数字、分组与极值检查 |

快速阅读可打开 [v1 精选样例](LoRA回答训练数据_v1精选.md)。最初的 20 条审阅样例仍保存在 `v0_review`，它们不是额外的训练分片，不能直接与 v1 拼接，否则可能重复或跨划分。

## 一条训练记录的结构

```json
{
  "messages": [
    {"role": "system", "content": "回答风格及事实使用规则……"},
    {"role": "user", "content": "{\"question\":\"2019年德国的毛利率是多少？\",\"context\":{\"period\":\"2019年\",\"country\":\"德国\",\"display\":\"58.70%\"}}"},
    {"role": "assistant", "content": "2019年，按汇总估算毛利除以汇总估算销售额计算，德国的估算毛利率为 **58.70%**。"}
  ]
}
```

上面为结构示意，省略了真实文件中的完整系统提示、指标定义、状态和限制。`content` 是字符串，因此内部 JSON 的引号使用反斜杠转义；不是文件乱码。JSONL 每行包含这样一个对象，JSON 则把全部对象放在数组中。

训练时输入是问题和可信查询上下文，目标是 assistant 回答。未来训练代码需要匹配具体框架的聊天模板，只对目标回答计算监督损失；本次没有预先套入 Qwen 特殊 token，也没有生成思考过程。实际训练前仍需用选定 tokenizer 检查样本长度，不能默默截断关键事实。

## 已采用的表达风格

- 毛利率采用“时间，按……计算，国家的估算毛利率为……”的顺序。
- 订单数先给结果，再说明：“当同一订单包含多件商品时，也只计一单。”
- 活跃客户数也使用完整条件句解释去重，避免短句堆叠。
- 金额保持精确值和美元单位，不让模型自行换算成“万”；毛利率由代码格式化为百分比。
- 金额、毛利、毛利率保留“估算”；无数据、查询失败、分母为零、并列和覆盖不完整均如实解释。
- 国家用中文，完整年度用“2019年”，不用生硬的起止日期参数代替自然表达。

这些句式由人工编写后程序填入事实，没有调用另一个模型批量生成。它们适合首轮固定表达风格的微调，问法与句式的多样性有限，不等同于大量独立人工对话。

## 来源与数据隔离

真实样例通过现有 `run_metric()` 取得数据库汇总，覆盖六个指标、八个客户国家及全部国家汇总、月份分组、国家极值和日期覆盖边界。国家排名由代码精确比较 Decimal 数值，保留并列，并非让回答模型自行排序。

模拟样例包括无匹配记录、真实计数为零的情境、分母为零、结果截断、并列、变化的金额，以及不同日期的数据快照只覆盖部分年度的情境。模拟快照的覆盖日期可能不同于真实数据库，来源明确记录为 `synthetic`；不能用于真实业务报表。`authored_flow` 则是手工编写的补条件、不支持和查询失败情境。

训练消息中不放来源标签，避免模型依赖“模拟”二字决定如何回答；来源保存在独立记录中，审阅精选也明确标注。服务端必须提供经过验证的 context，用户文本不能伪装成可信上下文。

数据按年度整体隔离：

| 划分 | 完整业务年度 | 其他情境 |
|---|---|---|
| train | 2016、2018、2019 | 2021 年真实部分覆盖；2015 年超出范围 |
| validation | 2017 | 2014 年超出范围 |
| test | 2020 | 2026 年超出范围 |

同一年度的所有市场、所有指标、汇总、分组、极值、不同问法及模拟值都在同一划分，避免德国某年的汇总在训练集中、同一年的国家分组却在测试集中。缺时间样例没有查询年度，按国家整体划分。同一事实有两种问法，数量不应解释为同等数量的独立事实。

各划分复用同一套风格模板，这是风格学习任务的有意设计。它们用于检查模型能否把固定表达应用到未用于训练的时间和结果，不是独立真实用户问法的泛化证明。后续仍需另建人工评测问题。

## 阅读生成脚本

`scripts/build_answer_style_dataset.py` 的重要代码均有中文注释。

| 函数或变量 | 作用 |
|---|---|
| `SYSTEM` | 从审阅脚本复用用户确认的回答规则 |
| `YEAR_SPLIT` | 指定查询年度属于哪个划分，先划分事实再生成改写 |
| `fetch()` | 只读查询并缓存；从快照中移除 SQL 和审计标识 |
| `context()` | 提供格式一致的可信上下文与业务定义 |
| `scalar_answer()` | 按确认的句式组织六个基础指标的目标回答 |
| `add()` | 生成消息，并独立保存来源、事实组及划分信息 |
| `build_real()` | 收集真实指标、分组、极值和覆盖范围查询 |
| `build_edges()` | 编写明确标记的模拟边界及反事实样例 |
| `build_flows()` | 编写缺条件、不支持指标和查询失败样例 |
| `validate()` | 检查结构、重复、事实分组、真实数值和用户原句 |
| `write()` | 固定种子打乱顺序，导出两种消息格式及审计记录 |

生成命令：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/build_answer_style_dataset.py
```

v1 已生成，脚本会拒绝覆盖非空的 v1 目录。后续扩充应先明确新版本并调整输出位置，保留本次数据和评测划分。脚本只依赖项目已有环境，运行需要数据库，不需要 Ollama。

无需重新查询数据库即可独立复核已导出的数据：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/validate_answer_style_dataset.py
```

该脚本不导入生成器，重新核对 JSON / JSONL 等价、消息结构、事实分组和快照隔离、真实数值与单位、月度行、国家极值及加粗数值来源。本次 1,110 条全部通过；这是数据完整性检查，不是模型效果评测。
